# Languages

Tokio is in English and Spanish. Every text on screen, in main's notices and on the games and timer overlays comes from a locale file. No i18n library: `Intl` does plurals, numbers and lists.

## Locale files

- `src/common/i18n/locales/<tag>.json`, one flat file per language, named by its canonical BCP 47 tag (`en.json`, `es-419.json`). `import.meta.glob` picks a new one up with no code change: copy `en.json`, translate it, run `yarn test`.
- UTF-8 without a BOM, accented letters as they are, never `\u` escapes (tools turn them into raw characters).
- `"language.name"` is the language's name in itself ("Español"), shown in Settings → Language.
- Keys are dotted and grouped by area: `"settings.language.title"`. `MessageKey` is the keys of `en.json`, so `tsc` checks `t("x")` and template keys like ``t(`timer.names.${key}`)``.
- `{name}` is a placeholder. A `{x}` with no param stays as written, since some texts show variables like `{username}`. Pass ports, versions and ids as strings.
- `{count}` picks the plural and is formatted for the language (1,000). Plurals are `key#one`, `key#other`, plus `#many`, `#few`… where the language has them (`Intl.PluralRules(tag).resolvedOptions().pluralCategories`). `#other` is required; the `#` keeps them apart from snake_case ids like `tnt_ring`.
- `<link>Euler Stream</link>` and `{input}` put elements inside a sentence, so the word order is the translator's.
- A missing text falls back to English, then to the key. `locales.test.ts` fails on missing, extra or duplicate keys, mismatched `{params}` or `<tags>`, plural forms the language doesn't use, an empty `language.name`, a BOM, and a file name that isn't a canonical tag.

### Blocks

Both files keep the same order, in blocks by owner: `language.name`, the shared blocks (`common.*`, `list.*`, `nav.*`, `titlebar.*`, `splash.*`, `app.*`, `triggers.*`, `roles.*`, `gifts.*`, `voiceKeys.*`), then one block per area, then `minecraft.*` and `timer.names.*` last:

| Block                                        | Starts with                          |
| -------------------------------------------- | ------------------------------------ |
| `components.*`, `layout.*`, `format.*`       | `components.deleteModals.soundTitle` |
| `home.*`, `settings.*`, `about.*`, `tools.*` | `settings.language.title`            |
| `tts.*`, `music.*`, `alerts.*`               | `alerts.editor.title`                |
| `games.*`, `overlays.*`                      | `games.overlay.noName`               |
| `main.*`                                     | `main.tray.open`                     |

- Add a key at the end of its area's block, in both files, and never edit lines you didn't add: parallel branches then merge without conflicts.
- Reuse `common.*` (Save, Cancel, Delete, Remove, Close, Test…) for the same word in the same role. Another word gets its own key in its area.

## Using it

- **Windows:** `useT()` (`@/ui/i18n`) returns `t(key, params)` in the window's language; `useLanguage()` returns the tag, for `Intl` and helpers. Without `LanguageProvider` both give English, so components render alone in tests.
- `LanguageProvider` sits at the top of the main window (`App.tsx`), the splash and the music window. It starts from `?lang`, which main adds when it loads a page (`loadPage`, the music title bar), follows the `LANGUAGE` push, and sets `<html lang>`. The splash has no preload, so it keeps `?lang`. Only `@/common` and `@/ui` aliases: the music build has no others.
- `rich(t("x"), { link: (text) => <a>{text}</a>, input: <Input /> })` fills `<tag>…</tag>` with a function and `{name}` with a node, only for the names given.
- Module constants hold keys, translated at render: `NAV_ITEMS`, `ALERT_TRIGGER_LABELS`, `ROLE_NAMES`, `TRIGGER_OPTIONS`, `COIN_OPERATORS`, the Minecraft step names. `useOptions(OPTIONS)` translates a list of `{ value, label: MessageKey }` for a `Select`.
- Helpers that write text or numbers take `language`: `formatStat`, `coinsLabel`, `giftsLabel`, `coinUnit`, `statText`, `triggerSummary`, `giftNames`, `gameEventText`, `gameStepsText`, `gameOverlayRows`, `timerTriggers`. Outside React, `translate(language, key, params)`.
- `listOf(language, items, { type: "and" | "or", max })` joins a list with `Intl.ListFormat`, counting the rest past `max` (`list.more`): "Rose, Lion, or 2 more". Don't join with `" or "` by hand.
- **Main:** `t(key, params)` and `language()` from `@/helper/i18n`. `onLanguage(listener)` redraws what main drew: the tray menu, the games and timer overlays, each music title bar (removed when its window closes).
- `tts/common` and `tts/providers/edge/**` may only `import type` from `@/common/i18n`: `yarn tts:edge:check` runs them under `tsx`, which can't load the locale files. So `VoiceEngine.keyLabel` is a `MessageKey` the window translates.
- **Lint:** `react/jsx-no-literals` (an override in `.oxlintrc.json` for the windows' TSX, tests left out) fails on text written into JSX, and into the `title`, `label`, `aria-label`, `description`, `placeholder`, `confirmText`, `hint`, `empty`, `alt` and `feature` props. Its allow list holds brand names and symbols. A prop that takes a key gets another name (`ProviderForm`'s `labelKey`). It doesn't see text in ternaries, module constants or helpers: those take keys too.

## The setting

- `settings.language` is `"system"` (the default) or a tag. Any string loads, so a language removed later can't break the store.
- `resolveLanguage(setting, preferred)` takes the saved tag when there's a file for it, else the first OS language that matches a file exactly or by its base language (`es-PE` → `es-419`), else English. It reads Linux's `es_PE.UTF-8` and skips `C`, `POSIX` and `@modifier` entries with string operations: `new Intl.Locale("C")` throws.
- The OS list is `app.getPreferredSystemLanguages()`, or `TOKIO_LANG` when set (e2e and `drive-app --lang`).
- Main applies it three times: in `whenReady` from the store file read directly (`savedLanguage`; a BOM is stripped, any error is `"system"`), so the splash shows it; in `startApp` right after the store loads, before any notice; and on `SET_LANGUAGE`. `LOAD_APP` replies `LANGUAGE` before its own reply, every load.
- `SET_LANGUAGE { language }` takes `"system"` or a tag in `APP_LANGUAGES`, saves, applies, replies `LANGUAGE` and the settings, and throws `saveFailure()` after a failed write. No success notice: the whole window shows the change.

## What stays English

- Logs, except `report()`'s line, which carries the notice's text. A log line next to a notice names the trigger with `translate(DEFAULT_LANGUAGE, …)` (`events/init.ts`).
- Minecraft's mob and item names (also ids), TikTok's gift names, the profile "Default", chat commands, alert ids, variables like `{username}`, and Tokio, LIVE, TTS.
- What the OS draws: file dialogs, native `<video>` controls, macOS's app menu.
- Official and third-party overlays get no language. Official overlays' names and descriptions come from the catalog, in English.
- The timer's carousel names left blank follow the language (`timer.names.*`); a saved name equal to its old English default reads as blank. Names the streamer typed stay as typed.

- Notices name an alert or game action by its trigger in quotes, “Seguir”: the triggers' names are verbs and nouns, which "la alerta de …" can't take alike. The editor's title is "Alerta: {trigger}".
- Minecraft's own menus and names are as Bedrock's `es_MX.lang` has them (Mojang's `bedrock-samples`): Ajustes → General → Ajustes de red → Activar WebSockets, trucos, evocador, Impulso en salto, Daño instantáneo.
- A sentence whose verb follows a count of people gets plural keys even when English needs none (`home.activity.joined`).
- The default font, Archivo, is also the Spanish word for file, so `common.defaultFont` (what the Games and Tools font fields show for it, and the font picker's first row there) reads "Archivo (predeterminada)". An overlay's settings show `components.overlayModal.overlayFont` instead, since its own font isn't Archivo.
